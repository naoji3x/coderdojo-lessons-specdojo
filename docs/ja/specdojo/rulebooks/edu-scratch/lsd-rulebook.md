# 投影スライド Rulebook

Lesson Slide Deck Rulebook

Scratch 授業で投影する Slidev スライドの置き方、ページ構成、説明方法、確認方法を定める。活動ごとのねらいと素材に合わせて具体化しつつ、学習者が作る・試す・振り返る流れを一貫して支える。

## 1. 全体方針

- 対象は Scratch 授業または同等の活動で、学習者に投影して進行する Slidev の `slides.md` とする。
- スライドは説明を読む資料ではなく、観察、制作、実機確認、振り返りを促す授業進行の補助として書く。
- 1 枚には 1 つの学習上の問い、手順、または到達確認を中心に置き、文章と図を詰め込みすぎない。
- 活動固有のテーマ、所要時間、概念、キャラクター、色、Scratch の名前は、その活動の指導案と実際の教材に合わせる。

## 2. 位置づけ

投影スライドは、指導案に沿う授業進行を学習者に見せる Markdown 成果物である。`slides.md` を Slidev で表示し、必要なローカル素材とコンポーネントを同じ活動ディレクトリで管理する。

| 要素                 | 役割                                       | この rulebook での扱い                       |
| -------------------- | ------------------------------------------ | -------------------------------------------- |
| 指導案               | 学習目標、活動、時間配分を定める           | スライドの主題と順序の根拠にする             |
| `slides.md`          | 投影するページの正本                       | この rulebook の対象とする                   |
| 素材・コンポーネント | 図、画像、再利用可能な表示部品             | 活動ディレクトリに置き、用途に応じて参照する |
| `style.css`          | 文字、余白、案内役、意味を持つ部品の見た目 | `slides.md` と同じ活動ディレクトリに置く     |

## 3. ファイル命名・ID規則

- スライドの正本は `courses/<course-id>/lessons/<nnn>-<activity-id>/slides.md` に置く。
- `<nnn>` は活動の順序を表す 3 桁の連番、`<activity-id>` は活動を区別する小文字ハイフン区切りの名前にする。
- 活動固有の画像などは `assets/`、フロントマターやコンポーネントから参照する公開素材は `public/`、活動固有の表示部品は `components/` に置く。
- `dist/` と `node_modules/.slidev/` は生成物なので Git 管理しない。投影内容を変えるときは生成物ではなく `slides.md` と必要な入力素材を変更する。
- 投影スライドの kata（sample・template）の ID は `lsd-` で始め（例: `lsd-sample`、`lsd-workshop-sample`）、`docs/ja/specdojo/samples/` または `docs/ja/specdojo/templates/` の下に置く。整形（prettier の `slidev` parser）と markdownlint の Slidev 用の規則は、この名前で Slidev のスライドを見分けて当てる。

## 4. 推奨 Frontmatter 項目

最初の YAML frontmatter には、少なくともテーマとタイトルを置く。レイアウトや配色などのページ固有設定は、各ページの区切り直後に置く。

| 項目             | 必須       | 書き方・判断基準                                   |
| ---------------- | ---------- | -------------------------------------------------- |
| `theme`          | 推奨       | `neversink` を指定し、活動で統一した部品を使う     |
| `title`          | 必須       | 表紙の題名と対応し、活動の内容が分かる名前にする   |
| `info`           | 推奨       | 授業で扱う内容を簡潔に説明する                     |
| `layout`         | ページごと | そのページの目的に合うレイアウトを選ぶ             |
| `color`、`class` | 必要時     | テーマ上の視認性や節の区別を支える場合だけ指定する |

- frontmatter の直後には `<!-- markdownlint-disable MD003 MD022 -->` を置く。
- この注釈は Slidev のページ設定が通常の Markdown と異なるための限定的な回避策であり、ほかの Markdown 規則を止めない。
- 注釈はページの先頭に置く。ページ末尾に置くと発表者メモとして扱われることがある。

## 5. 本文要件

活動の規模に応じてページを増減してよいが、次の役割を過不足なく含める。

| ページの役割 | 必須               | 内容                                                       |
| ------------ | ------------------ | ---------------------------------------------------------- |
| 表紙         | 必須               | 題名、回数または時間、活動への短い導入を示す               |
| めあて       | 指導案で求める場合 | 学習者が作るものと達成条件を具体的に示す                   |
| 節の扉       | 推奨               | 新しい概念や制作段階の開始を、短い主題と期待で示す         |
| 説明・制作   | 必須               | 概念、手順、Scratch のブロック図、試す行動を結び付ける     |
| まとめ       | 推奨               | 標準完成、発展、困ったときの試し方を確認する               |
| ふりかえり   | 指導案で求める場合 | 使った考え方と作品の変化を問い、次の活動とのつながりを示す |

- ページは `---` だけの行で区切る。設定が必要なページは区切りの直後に設定を書き、その下を `---` で閉じる。
- 表紙、節の扉、説明、まとめ、ふりかえりの順は学習の流れの一例とする。必要な役割と順序は指導案に合わせ、手本が 1 件だけである現時点では、めあてとふりかえりをすべての活動で必須にはしない。
- 完成見本を先に遊ぶ、または観察するページを置く場合は、「何が変わったか」のように、制作につながる問いを明示する。

## 6. 記述ガイド

### 6.1. レイアウトと情報量

- 表紙には `cover`、節の切り替えには `section`、説明には `top-title` や 2 列レイアウトのように目的が分かるレイアウトを選ぶ。
- 2 列の説明ページでは、手順・問い・注意を一方に、Scratch のブロック図や比較対象をもう一方に置く。
- 到達確認と発展は、チェック項目や短い選択肢で並べ、学習者が次にすることを判断できるようにする。
- スライド内の色、アイコン、節の見た目は概念の区別を助けるために使い、色だけに意味を依存させない。
- `neversink` の `SpeechBubble` は短い導入や励まし、`StickyNote` は観察の問い、`Admonition` はデバッグなどの注意を強調するときに使う。目的に合わない場合は部品を増やさない。
- 文字の大きさ、余白、部品ごとの見た目は活動の `style.css` にまとめ、`slides.md` と同じ活動ディレクトリに置く。Slidev は `style.css` を全ページに自動で読み込む。各ページで個別指定しない。見出しの基準サイズは変えず、`p`、`li`、テーマの部品などを対象に調整する。
- `slides.md` の中の `<style>` は、`<style src>` を含めて、そのページだけに効く（Slidev が scoped にする）。全ページに効かせる見た目には使わない。
- レイアウトごとの規則（例: 表紙の `.slidev-layout.cover p`）は、テーマのレイアウトにも同じ強さの規則があり、テーマが後から読み込まれて勝つことがある。`.slidev-layout.cover.cover p` のように class を重ねて強くする。
- `edu-scratch:lsd-sample` と将来作る `edu-scratch:lsd-template` は、見た目を kata と同じ名前の付属の `.css`（例: `lsd-sample.md` に対する `lsd-sample.css`）に置く。活動で使うときは、付属の `.css` を活動ディレクトリへ `style.css` として写す。`tools/preview-lsd.sh` も同じように写して表示する。

### 6.2. `style.css` の class

`style.css`（kata では付属の `.css`）には、次の class を定義する。各ページでは目的に合う class を省略せずに付ける。

| class                          | 付けるページ・要素                    | 役割                                                                                           |
| ------------------------------ | ------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `teacher-cat`                  | 案内役を囲む要素                      | 右下へ固定する                                                                                 |
| `section-slide section-<種類>` | `section` レイアウトの節の扉          | 左線・見出し下線の色を種類ごとに変える。`<種類>` は `observe`、概念名、`reflection` などとする |
| `device-check`                 | 実機で確かめる説明の `p`              | 実機確認を目立つ案内枠にする                                                                   |
| `check-list`                   | めあての `ul`                         | 到達条件を大きく読みやすく並べる                                                               |
| `completion-grid`              | 標準完成を示す複数の `div` を囲む要素 | 完成条件を格子状に並べ、案内役との余白を確保する                                               |
| `mission-list`                 | 発展ミッションの `ul`                 | 発展項目を大きく読みやすく並べる                                                               |

- 本文の `p` と `li`、`SpeechBubble` と `StickyNote` の本文は、教室の後方から読める大きさにする。
- 節の扉には必ず `section-slide` と種類を表す `section-<種類>` を併記する。説明ページで実機確認を書く場合は `margin: tight` と `device-check` を併用する。

### 6.3. 案内役のキャラクター

- 案内役を使う場合は、`teacher-cat` class を付けた要素を各ページの右下に置く。位置と大きさは活動の `style.css` で決め、画面外を指すと表示されない `v-drag` は使わない。
- 案内役は `:: note ::` の中に置かない。`:: note ::` の配置に引きずられて本文と重なるのを避けるためである。2 列のページでは、手本と同様に `:: left ::` または `:: right ::` の中に置いてよい。
- 案内役を使う場合は、表紙、めあて、節の扉、説明、まとめ、ふりかえりで継続して配置し、授業の語り口をそろえる。
- `role="img"` と内容が分かる `aria-label` を付け、装飾が情報を隠さない位置と大きさにする。
- 表情やポーズは、励ます、考える、困りごとを示すなど、そのページの学習行動と対応させる。
- `neversink` のキャラクター部品は大文字・小文字を正確に使う。たとえばリュックは `BackPack` であり、`Backpack` ではない。
- 活動にキャラクターが不要な場合は、無理に追加せず、同じ役割を見出しと短い案内文で果たす。

### 6.4. Scratch のブロック図

- Scratch のプログラムを説明する際は、活動の `components/ScratchBlocks.vue` と `ScratchBlocks` コンポーネントを使う。
- コンポーネントの直後と直前には空行を置き、内部には `text` のコードブロックで scratchblocks 記法を書く。
- `label` には図の目的を短く書き、`scale` はページの余白と可読性を見て調整する。
- スプライト、変数、メッセージ、背景の名前は活動で使う名前に合わせる。C 型ブロックを閉じる `end` も含め、ブロック図を画像だけで置き換えない。

### 6.5. 実機での確認

- ブロック名、メニュー位置、引数、座標の安全な範囲、クローンの間隔など、端末や素材に依存する値は実機で確かめるよう明記する。
- 確認文は「Scratch 3 で実機で確かめる」のように行動を明示し、何を確認するかと、確認後に何を動かすかを続けて書く。
- 手順を説明した直後に、旗から始める、1 つの対象で動かす、数値を変えて比べるなどの小さな試行を促す。
- うまくいかないときは、変更を 1 つに絞って再実行し、意図を先生や友だちに伝えるというデバッグの行動を案内する。

### 6.6. Markdownlint の注釈

- `slides.md` の markdownlint は、教材リポジトリの `.markdownlint.yaml` の設定に従う。文書内で規則を無効化する注釈は、先頭の `markdownlint-disable MD003 MD022` だけにする。
- 投影スライドの kata は、kata のリポジトリの `.markdownlint-slidev.yaml` の規則で検査する。VS Code では `.markdownlint-cli2.yaml` の `overrides` が、名前（3 章）で見分けた kata にこの規則を当てる。commit hook の markdownlint-cli はファイルごとに規則を変えられないため、`.markdownlintignore` で検査から外す。
- 見出し、リスト、コードブロック、表などは教材リポジトリの Markdown 規則に従い、注釈を書式の不備の回避に使わない。
- Slidev 固有のページ設定を変更したら、注釈が先頭にあり、MD003 と MD022 だけを対象にしていることを確認する。

## 7. 禁止事項

- `slides.md` を活動ディレクトリ以外に置いたり、活動ごとに複数の正本ファイルを作ったりしない。
- `dist/` と `node_modules/.slidev/` は生成物なので Git 管理しない。
- Scratch のブロック図は `ScratchBlocks` と `text` の記法を優先する。画像が必要な場合は `assets/` または `public/` に置き、出典と利用条件を記録する。
- 固有の端末で未確認のブロック名、選択肢、座標、タイミングを確定した事実のように書かない。
- 目的のない装飾、読めないほど小さい文字、色だけで区別した説明で学習の手がかりを減らさない。
- `slides.md` の `markdownlint-disable` 注釈で、MD003 と MD022 以外の規則を無効化しない。markdownlint の規則は教材リポジトリの `.markdownlint.yaml` に従う。
- 1 回の Slidev ビルドに複数の `slides.md` を渡して、別の活動の `public/` やコンポーネントを共有前提にしない。
