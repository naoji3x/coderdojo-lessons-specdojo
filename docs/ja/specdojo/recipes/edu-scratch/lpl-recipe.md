# 活動別指導案を組み立てる Recipe

Lesson Plan Authoring Recipe

1 回の Scratch 活動について、学習者が何を作り、どのように試し、何を根拠に到達を確かめるかを一貫して書くための手順である。活動の題材や時間を先に決め打ちせず、確認済みの条件から授業として実行できる計画にする。

## 1. このレシピの使い方

着手前に入力を集め、ねらいから完成形と見取りを決めてから、授業の流れと支援を組み立てる。本文を上から順に使い、各判断が後の表や文章で確認できる状態にする。

- コースで引き継ぐ学習経験と今回の到達目標を区別し、今回扱うことだけを指導案へ書く。
- ねらいを、学習者が作品で示す動き、操作、または説明へ変換する。作り方だけを先に並べない。
- 情報が不足している場合は、確認者と確認時期を決めて `_TODO_:` と記す。選択肢があり決めていない場合は `_UNDECIDED_:`、仮の前提で進める場合は `_ASSUMPTION_:` と記す。
- 一つの重要な判断について、「なぜ必要か」「何を到達とするか」「どう授業で扱うか」「どこで確認できるか」を、ねらい、完成形、流れ、見取りの対応でたどれるようにする。

## 2. 作成前に集める情報

次の情報を短いメモにまとめる。確認できた事実と、これから確認する事項を混ぜない。未確定の入力はラベルと確認方法を残し、もっともらしい値で埋めない。

| 入力               | 書き手が答える問い                                                 | 具体化のコツ                                                                 |
| ------------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| コースでの位置づけ | 何を引き継ぎ、今回の後に何へつなぐか                               | 確認済みのコース計画の範囲だけを要約し、未確認の資料から内容を補わない。     |
| 対象経験と到達目標 | 学習者は何を経験済みで、授業後に何をできるようにするか             | 「知る」だけで終えず、作品の動き、操作、説明のいずれで示すかまで書く。       |
| 時間と授業条件     | 利用可能時間、人数、端末、ネットワーク、投影はどうか               | 準備・片付け・共有を含めた時間を確認し、固定的な分数配分を持ち込まない。     |
| 利用環境と教材制約 | 使用する環境、素材、拡張機能、学校の運用条件は何か                 | 実機で確認済みのことと、確認待ちの操作・挙動を分ける。                       |
| 素材と開始状態     | 完成見本、開始用プロジェクト、素材は何を用意し、何を学習者に残すか | 初期化、終了、再開に必要な状態を洗い出し、配布物で消える制作機会を確かめる。 |
| 実機確認状況       | どの端末で、開始から保存・共有まで試したか                         | 未確認なら `_TODO_:` に確認者、端末、時期を添える。                          |

## 3. 全体の作成手順

1. 位置づけと制約を一文ずつ書き出す。前後のつながりは確認済みの範囲にとどめ、未確定の接続はラベル付けする。
2. 到達目標を、観察できる完成形へ分ける。時間不足でも残す最低到達、通常目指す到達、選べる発展を定め、それぞれに見取る証拠を付ける。
3. 完成形を実現する操作を、学習者が試せる小さな段階へ分ける。各段階に「操作する」「動かして確かめる」「一つ変えて比べる」のいずれを置くか決める。
4. 準備を決める。完成見本は開始・途中・終了・再開を実機で確かめ、開始用プロジェクト、素材、端末、投影、保存先を必要な範囲で用意する。
5. 授業の流れを表にし、各区間の時間、活動、確認、教師の留意点を対応させる。時間を合計し、所要時間との差があれば区間または到達線を直す。
6. 進度差と時間不足を扱う順序を決める。早く終えた学習者の改造・説明、遅れた学習者が最低到達へ戻る支援、省略または後回しにする活動を明記する。
7. 完成形ごとの見取り、つまずきへの声かけ、保存・共有、振り返りを追加する。授業中のどの場面で何を見るかを流れへ結び付ける。
8. 仕上げチェックを行い、ねらい、完成形、操作段階、時間、見取りの対応が途切れていないことを確認する。

## 4. 各章の書き方

| 章                       | 書き手が答える問い                                               | 具体化のコツ                                                                                   |
| ------------------------ | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 授業の概要               | 誰が、どの時間と条件で、何を作りながら何を学ぶか                 | 対象、所要時間、テーマ、ねらい、主な機能を置き、各機能には作品で果たす役割を添える。           |
| 授業の位置づけ           | 前の経験のどれを使い、今回の経験をどこへつなぐか                 | 前後の回名だけでなく、引き継ぐ概念や制作経験を短く示す。次回がない場合は、その扱いを明記する。 |
| 完成する作品             | 旗や入力からどんな振る舞いが起こり、何を最低・標準・発展とするか | 各到達は観察または説明で判定できる文にする。発展は標準到達を壊さず、選んで試せる工夫にする。   |
| 事前準備                 | 授業前に何を用意し、開始・終了・再開をどう確かめるか             | 完成見本で実機確認すること、配布物に入れるもの、学習者が作るために残すものを分ける。           |
| 授業の流れ               | どの区間で何を操作・確認・改造し、何分使うか                     | 各行に時間、活動、学習者の確認、指導上の留意点を対応させ、合計時間を明記する。                 |
| 進め方と進度差への対応   | 誰が先にできたとき、または遅れたときに次に何をするか             | 待たせる指示ではなく、前者には改造・説明、後者には最低到達へ戻る具体的な支援を置く。           |
| 評価・見取り             | 最低・標準・発展の到達を、作品・操作・説明・振り返りの何で見るか | 「できた」ではなく、旗から動かす、変化を比較する、仕組みを説明するなどの証拠にする。           |
| 声かけとつまずきへの対応 | どの場面で何を問い、何をどの順で確かめるか                       | 原因を決めつけず、まず動かす箇所、次に比べる変更を示す。実機未確認の挙動は確認事項にする。     |
| まとめと次回へのつなぎ   | 何を振り返り、保存・共有をするか、次に何を渡すか                 | 保存先、共有相手、方法、時間を決める。扱わない場合も、授業での代替の扱いを書く。               |

## 5. 深掘り手順

内容が一般論に見えるときは、次の順で具体化する。

1. ねらいごとに、学習者が見せる作品の状態または説明を一つ書く。書けないねらいは、到達目標が広すぎるか、観察方法が不足している。
2. その状態を作るための操作と、操作直後に確かめる動きを対応させる。操作に対応しない確認や、確認できない操作は見直す。
3. 最低到達に届かない場合の支援と、標準到達を終えた場合の次の活動を並べる。どちらにも具体的な次の行動がなければ、支援計画を補う。
4. 重要な主張が、位置づけ、完成形、流れ、見取りのどこで確認できるかをたどる。たどれない主張は、根拠を確認するか、記述を外す。

## 6. 良い例 / 悪い例

| 観点           | 良い例                                                                                            | 悪い例                                                               | 理由                                                       |
| -------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| ねらいと完成形 | 「入力で動きを変え、変えた値と作品の変化を説明する」とし、標準完成形に入力・変化・説明を置く。    | 「入力を学ぶ」とだけ書き、完成形は見た目の完成だけである。           | 良い例は到達を観察でき、悪い例は何を見取るか決められない。 |
| 時間と優先順位 | 区間時間を合計し、時間不足時は発展の改造を後回しにして最低完成形を残す。                          | 区間の合計を確かめず、遅れた場合も全活動を同じ順で行う。             | 良い例は実施可能性と最低到達を両立できる。                 |
| 進度差への対応 | 早い学習者には変更の比較と説明を、遅れた学習者には完成見本を使った最低到達の確認を置く。          | 早い学習者には待つよう求め、遅れた学習者には「がんばる」とだけ書く。 | 良い例は双方の次の行動を授業内で選べる。                   |
| 見取り         | 「開始から動かし、意図した変化を示し、どの変更が効いたかを説明する」を見る。                      | 「作品が完成したかを見る」とだけ書く。                               | 良い例は作品、操作、説明の証拠を授業の場面で集められる。   |
| 実機確認       | 「開始、終了、再開、保存を対象端末で確認済み」と書く。未確認なら確認者と時期を `_TODO_:` で残す。 | 未確認の端末挙動を、使える前提で断定する。                           | 良い例は授業直前に必要な確認を追跡できる。                 |

## 7. レビュー観点

| 観点             | 確認すること                                       | 判定の目安                                                     |
| ---------------- | -------------------------------------------------- | -------------------------------------------------------------- |
| 位置づけ         | 前後とのつながりが確認済みの情報に基づくか         | 未確認の資料や推測した学習内容を根拠にしていない。             |
| 到達の整合       | ねらい、主な機能、完成形、活動、見取りが対応するか | 各ねらいを、少なくとも一つの完成形と見取りで説明できる。       |
| 実施可能性       | 準備、時間、端末、素材、実機確認が授業条件に合うか | 区間の時間合計が所要時間と一致し、未確定事項に確認方法がある。 |
| 進度差           | 最低到達、支援、省略候補、発展が矛盾しないか       | 遅れた学習者が最低到達へ戻れ、早い学習者が待機しない。         |
| 見取りと振り返り | 授業中に集められる証拠になっているか               | 作品、操作、説明、または振り返りの具体的な行動で判定できる。   |
| 保存・共有       | 保存・共有の有無、方法、時間が明確か               | 行う場合は実施方法を、行わない場合は代替の扱いを説明できる。   |

## 8. 仕上げチェック

- [ ] 入力情報のうち未確認・未決定・仮定の項目に、`_TODO_:`、`_UNDECIDED_:`、`_ASSUMPTION_:` のいずれかと次の確認行動を記した。
- [ ] ねらいごとに、観察可能な完成形、必要な操作、授業中の見取りを対応付けた。
- [ ] 最低完成形は時間不足時にも残る到達であり、標準完成形と発展形の優先順位を説明できる。
- [ ] 授業の流れの時間を合計し、所要時間との一致を確認した。不一致なら区間または到達条件を修正した。
- [ ] 準備には、実機確認、素材・端末、開始状態、終了・再開、保存・共有の扱いを必要な範囲で入れた。
- [ ] 早い学習者向けの改造または説明、遅れた学習者への支援、省略または後回しにする活動を決めた。
- [ ] 見取りは「完成した」だけでなく、作品、操作、説明、振り返りのいずれで確かめるかを記した。
- [ ] 題材固有の値、時間、機能名、端末挙動を、他の活動にも当てはまる規則として書いていない。
