# PJR-XVR2 第2回の指導案を、先生と一緒に操作する進め方に直す

## 1. 概要

指導案の kata の手本にする前に、第2回の `lesson-plan.md` を直す。先生と一緒に画面を見ながら操作する進め方を主体にし、基本制作の時間の内訳・クローンとクリア後のつまずき・評価・発展の時間の使い方・保存と見せ合いを加える。

対象は coderdojo-lessons の `courses/scratch-basic/lessons/020-balloon-game/lesson-plan.md`（実行中は `$SPECDOJO_REPO_CODERDOJO_LESSONS` からたどれる）。根拠にする文書は次のとおりで、読み取り専用とする。

- `docs/course-design/course-plan.md`（コース計画。第2回の内容、各回の時間配分、指導上の方針）
- `courses/scratch-basic/lessons/020-balloon-game/slides.md`（第2回の投影スライド）

`docs/course-design/020-animation.md` は旧い第2回（棒人間のアニメーション）の設計のため、根拠にしない。

orchestrator のレビューで分かったこと:

- 分量（約115行）と時間配分（導入5分・基本制作25分・発展10分・まとめ5分）は、コース計画と一致しており妥当である。
- 基本制作の25分で、変数・乱数・クローン・メッセージと背景の4つを扱い、5回の中で最も詰まっている（コース計画にも「学習量が最も多い」とある）。
- 次の要素が欠けている: 基本制作の時間の内訳と合流点、クローンとクリア後のつまずき、評価（見取り）、届かなかった児童の発展の時間の使い方、作品の保存と見せ合いの形。

## 2. 完了条件

進め方:

- 基本制作を、先生の画面に合わせて全員が同じ手順で進める「一緒に操作する」形を主体にしている。各段階（得点・乱数・クローン・クリア）の最後に、児童が自分で値や表示を変えて試す時間（1〜2分）がある。
- 早く終わった児童は、その段階の改造（数・表示・出方などを変える）を続けて時間を使うことが書かれている。
- 遅れた児童は、先生の画面をまねして同じ手順で作って追いつくこと、先生は全員が操作し終えたのを見てから次の段階へ進むことが書かれている。途中の段階のプロジェクトは配らない（配布の準備をしない）。
- 5章の授業の流れで、基本制作の25分の内訳（例: 得点5分・乱数5分・クローン10分・クリア5分）が分かる。導入・基本制作・発展・まとめの合計（5・25・10・5分）は変えていない。

内容:

- 4.1 の完成見本の要件と 5.1 の手順に、次が入っている。
  - 元の風船を隠し、クローンだけを表示する。
  - クローンは、クリックされたとき、または一定時間がたったときに消える。
  - 旗を押したとき、得点を0にし、背景を開始の背景に戻す。
  - 得点が10になったら、クリアのメッセージを送り、背景を切り替え、「すべてを止める」でゲームを止める。
- 6章のつまずきへの対応に、次が入っている。
  - 元の風船が表示されたまま残り、押すと得点が増える。
  - クローンが消えずに増え続け、画面が埋まる・動作が重くなる。
  - クリアした後も風船が出続ける。
  - 2回目に旗を押しても、背景がクリア画面のまま始まる。
- 評価（見取り）の観点があり、最低完成形・標準完成形・発展形のどこに届いたかを、何を見て判断するかが書かれている（5章の表の列でも、節でもよい）。
- 発展の10分は、標準完成形に届いていない児童が標準完成形を目指す時間にもなることが書かれている。
- まとめに、作品を端末に `.sb3` 形式で保存することと、見せ合いの形（隣同士・数人の発表など、5分で収まる形）が書かれている。
- 最後の段階（クリア）の留意点に、時間が足りないときはこの段階の「変えて試す」を省き、発展の時間に回してよいことが書かれている。
- ブロックの正確な名称や配置は、使用する Scratch 環境で教師が確かめる、という既存の注意を残している。

形式:

- 章立て（1〜7章）は保ち、必要な節や表の列を加える形で直している。分量は、目安として160行以内に収まっている。
- 手本の授業の事実（対象・時間・テーマ・使用する機能・第1回と第3回とのつながり）は変えていない。
- 変更したファイルが、coderdojo-lessons の prettier と markdownlint の設定で検査を通る。

変えないもの・記録:

- `slides.md`・コース計画・ほかの文書は変更しない。直した指導案とスライドの流れが食い違う箇所は、個票の対応結果に列挙する（スライドの修正は別の作業にする）。
- 変えた点と、判断に迷った点を、個票の対応結果に書いている。

## 4. 対応結果

- `coderdojo-lessons:courses/scratch-basic/lessons/020-balloon-game/lesson-plan.md` を、先生の画面に合わせて段階ごとに操作し、先生が全員の操作を見てから次へ進む流れへ更新した。最初の3段階には1〜2分の「変えて試す」時間を置き、最後のクリア段階では時間が足りなければこの時間を発展へ回せるようにした。導入5分・基本制作25分・発展10分・まとめ5分は維持した。
- 先に終えた児童は数、表示、風船の出方などを改造して時間を使い、遅れた児童は先生の画面をまねして追いつくことを明記した。途中の段階のプロジェクトは配らない。完成見本、手順、つまずきへの対応に、元の風船を隠すこと、クローンをクリック時または一定時間後に消すこと、クリア後に「すべてを止める」こと、旗で開始背景へ戻すことを追加した。評価の見取り、標準完成形を仕上げる発展時間、端末への`.sb3`形式での保存と隣同士での見せ合いも追記した。
- スライドは変更しない。現在のスライドには、元の風船を隠す処理、一定時間後にクローンを消す処理、クリア後の「すべてを止める」、旗で開始背景へ戻す処理が明示されていない。指導案では完成見本の必須要件として扱うため、スライド改訂が必要かは別作業で判断する。
- 判断に迷った点はない。ブロックの正確な名称・配置は、使用するScratch環境で教師が事前に確認する既存の注意を維持した。

- 1回目の成果は完了条件をすべて満たしていた（128行、prettier と markdownlint を通る、指導案のほかは変えていない）。

  - 途中の段階のプロジェクトは、準備が大変なため配らない。遅れた児童は先生の画面をまねして追いつく。
  - 早く終わった児童は、改造を加えて時間を使う。
  - 保存は、端末に `.sb3` 形式で保存することで確定している。
  - 最後の段階の5分は詰まっているため、時間が足りないときは「変えて試す」を省いてよいと書く。
- スライドとの食い違い（上の4つ）は、別の todo で直す。
